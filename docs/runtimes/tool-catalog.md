# Complete tool and MCP catalog

This page inventories every first-party tool surface shipped by Cyberful: Pi-native tools, the phase gateway, the isolated browser, the ZAP bridge and official ZAP MCP add-on, Ghidra, and all tools published by cyberful-os. Availability is phase-scoped: a tool appears only when the selected workflow policy, runtime, and authorization permit it.

## Version semantics

Cyberful releases build the security image locally. Explicitly pinned dependencies show their exact version below. `Kali rolling, build-resolved` means the numeric package version is resolved and attested when the local image is built; documenting one static number would be inaccurate across later local builds. `ATT&CK build snapshot` means Enterprise, Mobile, and ICS versions are fixed by the official STIX index at the beginning of the Cyberful build and reported by `mitre_attack status`. `Cyberful release` means the tool is versioned with the application rather than as an independent package. The `tool_inventory` and `capability_attestation` tools provide the authoritative live-image state.

## agent-browser MCP

Cyberful pins the Cyberful agent-browser fork `0.34.0-cyberful.3`, discovers its full catalog once per phase through the direct `search` identity, and reuses the authorized definitions for all profile runtimes. Profiles `1`–`5` share one persistent phase session each and fail closed through ZAP; `search` is phase-ephemeral, direct, and natively confined to `*.duckduckgo.com` and `*.google.com`. Effective upstream tools are deferred behind `tool_search`, while the Cyberful `web_search` wrapper is eager. Cyberful adds `profile` to ordinary upstream schemas and removes host-owned allowlist, session, namespace, profile-path, restore, connection, proxy, extension, state, request-header, and lifecycle inputs.

## Completeness and runtime checks

The documented static surfaces comprise 12 Pi-native and session tools, 24 gateway tools, 23 browser tools, 14 official ZAP tools, 10 Cyberful ZAP bridge tools, 9 Ghidra tools, 5 cyberful-os utilities, 13 cyberful-os managed workflows, 3 cyberful-os library tools, and 203 cyberful-os CLI tools. The cyberful-os registry therefore contains 224 declared tools, of which 223 are exposed by the public build because the optional JEB wrapper remains hidden until a private image attests it. Phase policy intentionally exposes only the subset needed by the active persona. ZAP API operations are runtime-discovered through `zap_api_catalog`, because that operation set is defined by the installed add-ons rather than by a stable Cyberful registry.
