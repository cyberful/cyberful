# Framework and deliverable selection

Select the reporting profile before interpreting evidence. Record the exact framework, version, entity role, jurisdiction, assessment period, evidence cutoff, intended recipient, and whether an official template or qualified assessor is required. A request for “a compliance report” does not establish any of those facts.

Use the PCI DSS profile only for PCI DSS 4.0.1 reporting support. Its output is a draft evidence package for an official Report on Compliance workflow. Use the GDPR profile for an internal accountability and compliance-evidence report under Regulation (EU) 2016/679; do not rename it to an authority-issued certification.

The generic compiler is appropriate when a profile can express the required sections, evidence expectations, status vocabulary, and attestation boundary. Create a specialist skill instead of extending this router when a future regime requires materially different evidence collection, a dedicated toolchain, external submission, regulator-specific workflow, or a privileged assessor action.

Treat local law, sector rules, contractual obligations, supervisory guidance, card-brand rules, acquirer instructions, and customer-specific submission requirements as separate inputs. A framework profile does not silently absorb them.
